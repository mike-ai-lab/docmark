# Project Structure

## Root Directory

```
docmark/
├── src/                    # Source code (ES modules)
├── public/                 # Static assets
├── api/                    # Serverless functions (Vercel)
├── dist/                   # Production build output (generated)
├── index.html              # Main entry point
├── vite.config.js          # Vite configuration
├── package.json            # Dependencies and scripts
└── README.md               # Documentation
```

## Key Files

- **index.html** - Main HTML entry, loads Monaco Editor and app modules
- **src/main.js** - Application initialization, editor setup, event handlers
- **pagination-engine.js** - PDF pagination logic (root level)
- **pdf-server.js** - Local development PDF server (Puppeteer)
- **electron-main.js** - Electron desktop app entry point

## Module Organization Patterns

### Feature Modules
Each major feature is self-contained in its own directory:
- UI components
- Business logic
- Styles (if needed)
- README/docs (if complex)

### Import Conventions
- ES modules (`import`/`export`) in `src/`
- CommonJS (`require`) in Node.js files (api/, servers)
- External libraries loaded via CDN in index.html (highlight.js, DOMPurify, marked)

### State Management
- localStorage via storehouse-js wrapper
- Global state in `main.js` init closure
- Feature-specific state in respective modules

## Build Output (`dist/`)

Generated by Vite, contains:
- Bundled and minified JavaScript
- Processed CSS
- Copied public assets
- Optimized index.html

## Testing

- Test files in root (e.g., `pagination-test-merged.html`)
- Test documentation in `test-docs*/` directories
- Test results in `test-results/`

## Documentation

- Markdown files in root describe features and fixes
- `public/docs/` contains user-facing HTML documentation
- Feature-specific docs in module directories (e.g., `src/pdf-import/README.md`)
